# 阶段行为合同

本文件保留 FR-01 至 FR-10 的完整规范义务，对应 SPEC 的 CAP-1 至 CAP-10。failure-modes.md 明确 FR-07 的判定顺序；它不替代治理开启时现有合同。

### 4.1 配置与正式接入

#### FR-01：可维护且可核对的查询配置

维护者能够从仓库级配置确定查询入口、适用阶段、消费者身份、范围和有界预算，并检查解析后的有效值及来源。优先使用团队覆盖和现有解析器；升级覆盖的原生默认文件不能成为唯一持久配置。

遵守现有覆盖和数组合并语义；重复追加不能导致同一阶段同一触发重复执行。个人配置、模型输入和自然语言不能扩大仓库权限。必要配置缺失、配置非法和消费者不支持必须产生不同诊断，不得静默成功。

可观察结果：团队/个人覆盖后的有效值与来源可核对；重复触发被控制；缺失与非法输入的处理符合 FR-07。

#### FR-02：复用 Locator 并声明 BMAD 身份

BMAD 通过正式、受限的消费者身份查询；共享还是分阶段身份留给 Architecture。保持 Domain、Visibility、Lifecycle Instance、Enforcement Level 四维隔离及目录、策略、投影、发布绑定检查，不冒用 vdd 或 bootstrap。

所需消费者声明、策略生产来源及发布兼容增量纳入范围。不得手改生成投影、伪造发布记录或启用跳过发布/新鲜度检查的调试选项。初次需要有效新代次时，由维护者通过既有流程显式发布，日常查询不触发发布。

可观察结果：正式请求具备真实 BMAD 身份；权限和来源绑定未放宽；未发布或损坏绑定不能被空结果掩盖。

### 4.2 规划阶段实际消费

#### FR-03：PRD 默认查询

本仓需求 create 或实质性 update 在形成依赖仓库事实的范围判断前，执行针对性查询并读取影响判断的来源；不需要维护者额外提醒。输出区分已有且核实、仅有规划、明确排除/延期、拟新增及待核实。

纯排版/措辞且不改变事实判断时，可复用有效记录并写明理由。历史计划、勾选或报告不能独自证明实现完成。

可观察结果：查询和读取发生在结论前，实际改变复用/新增范围判断；纯编辑复用有可核对原因。

#### FR-04：Architecture 查询与 SPEC 承接

Architecture 在影响实现的决定前核对相关 Accepted ADR、owner、接口和当前实现，对照上游采纳结论，显式记录冲突与影响，不让索引摘要覆盖现行约束。

SPEC 保留有效能力、约束、排除项和未决问题；只为新问题、缺失依据或相关来源变化补查。继续使用 jimuyun-spec 所维护的 canonical SPEC 包、typed companion／provenance 和外部 selection commitment。只溯源的输入不能代替下游必须承担的规范内容。

可观察结果：来源冲突有处理；复用与补查理由可查；typed 角色、包完整性和 selection 规则保持有效。

#### FR-05：VDD 规划前查询与源码核对

VDD create／实质性 repair 在界定实现、消费者、测试和依赖切片前先查询，再读取当前源码、调用方、测试与控制契约。Locator 只缩小范围，不能替代调用链核查。

索引外文件可在授权范围内直接检索，记录为直接源码核查，不伪造成 Locator 返回。计划表达可复用能力、真实缺口及需要联动的消费者/测试；已存在行为应做回归验证，不能为制造 RED 走旧路径或重复实现。

可观察结果：未命中但源码已有能力时，计划采用既有能力并保留发现途径；写入边界和消费者检查有依据。

### 4.3 来源、失败与治理边界

#### FR-06：来源身份与采纳结论分开

影响判断的采纳信息保留查询主题、消费者、结果状态、来源定位、读取身份、简短结论及用途。相关但未采纳候选保留必要原因，不保存全部检索噪声。

索引快照、main、工作分支提交和未提交字节分别记录，不把旧发布快照改写为 HEAD，不把工作树新增能力声称为 main 已发布事实。已有 hash 验证合同继续执行，轻量查询不额外引入全仓冻结；正式计划和验收继续按原合同绑定。

可观察结果：读者可追溯每项影响范围的结论到底读了什么版本，能区分“已发布”和“候选”。

#### FR-07：可观察的失败与降级

消费者同时判断进程退出、超时/取消、输出可解析性、业务状态及来源完整性。退出码为 0、存在 JSON 输出或已生成文件，都不能单独证明查询成功。采用原始需求建议的以下产品语义；具体诊断/兼容映射由 SPEC 明确：

| 情况 | 普通规划查询或治理关闭 | 既有强制门禁 |
| --- | --- | --- |
| 命中且有效 | 读取后记录采纳/不采纳 | 继续原有门禁 |
| 未命中、低置信或歧义 | 定向核查源码，不能断言能力不存在 | required module 不满足则按合同阻断 |
| 已识别过期或相关来源变化 | 标记 degraded，核实当前来源，不消费失效候选 | 仅走现行 source_refresh/修复路径 |
| 确认入口不可用、未配置或超时 | 记录原因，改用独立源码核查；必要事实仍未知则停止依赖它的判断 | 不绕过 required gate |
| 非法请求/配置、未知或损坏状态、发布绑定损坏、越界或策略拒绝 | 停止消费并报错，修正后才继续受影响判断 | fail-closed |
| 用户取消 | 停止查询，保留未完成，不后台重试 | 保持取消/恢复边界 |

必要配置缺失可以被准确诊断后进入可用性处理；配置非法不得进入该降级通道。来源不能验证、约束冲突或事实缺口影响方案时应保留阻塞项。通用 blocked 无法判断原因时不能猜成未命中，需补最小只读诊断或适配。

可观察结果：退出码 0 的 blocked、损坏输出和越界不会被当成功或空结果；被拒绝内容不泄露。

#### FR-08：查询与治理解耦

保持现有治理优先级：显式选项覆盖环境配置，再按 phase state 解析；未设置 phase state 为 development，auto 在 development 关闭治理。默认查询不创建冻结知识、Skill-input attestation、额外授权、review lineage 或整套治理产物。

治理开启时继续强制校验、冻结和授权。若旧 ADR 与开发态轻量语义需要协调，由 Architecture 提出明确适用范围增量，不静默弱化正式模式。

可观察结果：development/auto 真实查询可发生而治理仍关闭；governance on 的 required module/完整性失败仍阻断。

### 4.4 恢复与交付证明

#### FR-09：局部刷新与有界上下文

任务意图和相关来源未变时可复用记录；进入新阶段或恢复时按实际依赖决定补查，不每轮加载全历史。相关变化只更新受影响结论和计划；无关代次/文件变化不单独触发整个需求重建、历史重写或全量重跑。正式计划有效性仍受原有范围绑定约束。

查询候选数、输出和调用次数必须有界，只装载支撑当前判断的片段。不得无限重试、自动发布或开启其他工作流修复查询。

可观察结果：相关变化产生局部更新；仅无关变化不触发重建；取消及预算耗尽不产生后台无限重试。

#### FR-10：真实消费验证与兼容交付

验证覆盖有效配置解析、阶段触发、真实查询/诊断、来源读取、结论被下游采用的完整链条。固定样例可验证确定性分支，但还需有界实际 BMAD 阶段与 VDD 消费样例；不得将伪造结果称为真实运行，不要求重跑历史全部需求。

保护 VDD compiler、Quick Dev TDD、SPEC 包完整性及 Acceptance 权威。针对实际改动路径回归，并单独验证 Windows 路径、编码、子进程行为；Linux 证据不能替代 Windows。

可观察结果：真实消费者记录能证明结论被采用，已有交接仍有效，未完成的平台验证明确标记。本 PRD 的内部检查不能满足未来功能实施 AC。

## 5. 跨能力质量要求

- **安全与权限**：配置覆盖和查询意图不能扩大仓库受控范围；损坏/越界结果不泄露内容，不绕过既有 gate。
- **可维护性**：官方 BMAD 文件保持字节原样，新定制外置；升级后仍可辨认有效配置来源，原生/外壳 owner 分清。
- **资源边界**：候选、输出、调用数设有限上界；Architecture 提出技术设计，SPEC owner 通过原生派生/refresh 固化下列数值和计量规则；后续修订仍由 SPEC owner 决定，不虚构延迟 SLA。
- **可审计性**：记录足以解释来源身份、失败、采纳和局部刷新；不建立第二套事实权威或全仓冻结。
- **兼容性**：保留正式治理与 typed SPEC/VDD/Quick Dev/Acceptance 合同；结果兼容策略先明确，再实施。


## 预算规范（本次 owner 收敛）

| 参数 | 默认 | 硬上限 | 计量边界 |
| --- | --- | --- | --- |
| max_candidates | 12 | 20 | 同一判断 episode 累计返回候选行，重复也计数 |
| max_output_bytes | 65536 | 131072 | 同 episode 累计交付 UTF-8 查询 JSON、诊断、源码摘录；最小合法值 4096 |
| max_calls | 3 | 5 | 同 episode Locator 尝试，失败、超时及补查均计数 |
| timeout_seconds | 30 | 60 | 每次子进程墙钟上限；取消立即终止 |

有效额度取仓库硬上限、团队设置、已发布 policy 既有上限与调用方更小请求的交集；personal/model 只能下调。值须正整数，bool、零、负数、错误类型、越界或输出额度小于 4096 均为非法配置，不静默夹取。合法 policy 限额更小则记录后取交集。相同判断的重试、重复 hook、恢复共享计数，不新建 episode 绕过额度；仅相关任务意图/输入变化可新建并记录前驱原因。

输出额度内部预留 4096 字节交付一次完整终止 JSON，普通交付不得消耗该预留；终止报告的固定长度标识、枚举、计数及至多 512 字节受控摘要须保证完整报告不超过 4096 字节，候选/读取数组为空，可空索引身份，原始诊断引用留在本地既有记录。预留不是额外预算。预算不足先终止报告再关闭 episode，不输出部分 JSON，不再后台重试；未知必要事实继续阻断相关判断。

子进程 stdout/stderr 各缓冲至多 65536 字节，合计至多 131072；超限终止，不解析截断 JSON。完整来源 hash 可流式计算，交付摘录仍计输出额度。预算设计不新建治理开关、冻结或发布；后续真实样例不适用时显式回到 SPEC owner 修订。

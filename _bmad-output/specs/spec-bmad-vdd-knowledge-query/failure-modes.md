# 查询结果与失败分流

本文件是 CAP-7 的规范 companion，沿用 FR-07 已批准的行为语义，不新建 Locator 公共 schema。以下名称描述消费者决策类别，不宣称是当前 CLI 已有状态字段。Architecture 必须把真实输出/只读诊断逐项映射到这些类别，并保留现有调用方兼容性；实施前不得以字符串猜测代替该映射。

## 判定规则

1. 一次查询必须同时考察进程退出/异常、超时、取消、输出可解析性、结构化业务状态和适用来源完整性。退出码 0、存在 JSON 或生成文件都不单独证明成功。
2. 先验证可消费性再采纳。已发现非法请求/配置、未知或损坏状态、发布绑定损坏、路径越界、策略拒绝时，不可信候选不得进入后续事实判断；即使同时报告命中、过期或空数组，也不降级为普通缺失。
3. 通用 blocked、非零退出或空候选本身不证明“入口不可用”。原因未获有效诊断时，按未识别失败停止受影响判断；修正或取得有效诊断后才重新决定。不得通过关闭校验消除失败。
4. 用户取消使本次查询未完成并停止，不后台重试；未验证部分不能记为成功。已观察到的完整性/权限错误保持错误记录，不因取消被改写为普通缺失。
5. 查询入口被可靠确认为未配置、不可用或超时，且没有将不可信结果拿来使用时，可记录原因并独立核查当前源码。必要事实无法确认、来源相互矛盾或不能验证时，停止依赖该事实的交付判断。
6. 进入直接源码核查不是 Locator 成功，也不是 required gate 替代品。治理开启时始终服从现有强制约束。

## 结果类别与允许动作

| 类别 | 普通规划查询 / governance off | governance on 或既有完整性门禁 |
| --- | --- | --- |
| 有效命中 | 读取相关原始来源，按合同核对 hash，记录采纳/不采纳 | 继续满足全部原有门禁 |
| 未命中 / 低置信 / 歧义 | 定向核查当前源码；不据此证明能力不存在 | required module 未满足按原合同阻断 |
| 已识别过期 / 选中来源变化 | 记录 degraded，核实当前相关来源，不把失效候选作为事实 | 只允许现行 source_refresh/修复路径，不扩大选中集合或改发布身份 |
| 已确认未配置 / 不可用 / 超时 | 有原因的独立源码核查；必要事实未知则保留未决并停止相关判断 | 不绕过 required gate |
| 非法请求/配置 / 损坏或未知输出 / 损坏绑定 / 越界 / 策略拒绝 | 停止消费并报错；修正后继续受影响判断 | fail-closed |
| 用户取消 | 停止、未完成、不自动重试 | 保持已有取消/恢复边界 |

## 配置与诊断边界

缺失必要配置须明确诊断，不能报告成功；能确认“未配置”时适用可用性处理。非法或不可读/损坏的已有配置不是正常未配置。不支持的消费者不准冒用已支持身份；策略拒绝保持 fail-closed。Architecture 定义实际诊断如何区分这些情况，不能通过模型自行猜因或空候选推断。

## 记录与恢复

记录查询主题、消费者、结果类别/原诊断、有关来源定位和读取身份、结论/用途或未完成原因。被拒绝的越界内容不得输出；安全诊断仅说明受影响范围与错误类型。预算耗尽、超时和取消不能启动无限重试或自动知识发布。

相关来源/意图未变化可复用有效记录；相关变化只补受影响部分。无关代次变化不单独使整个需求失效。需要强制治理修复时仍遵守已有合同，不借“轻量查询”跳过它。

## 兼容策略与诊断映射

既有 Locator 调用方继续得到原有字段、状态含义及退出码语义，不通过删除、重命名或重新解释现有返回值完成本增量。新增消费者可以在外置、显式接入的只读适配层得到细化诊断；原始业务状态和诊断依据必须保留。Architecture 确定实际表示与调用边界，不能改变以下映射或把新细化状态强塞给未迁移的消费者。

| 已核实的诊断依据 | 消费者归类 | 停止/继续条件 |
| --- | --- | --- |
| 命中且结构/策略/发布/读取完整性成立 | 有效命中 | 来源核对后才能采纳 |
| 有效未命中、低置信或歧义 | 未命中/低置信/歧义 | 定向源码核查；required gate 仍按旧合同 |
| 能识别的索引过期或同一选中来源字节变化 | 已识别过期/来源变化 | degraded；只能核实当前来源或走已允许刷新 |
| 明确缺少配置项/入口；已确认不可用；已确认超时 | 已确认未配置/不可用/超时 | 停止使用本次结果；独立核查，必要事实仍未知则停 |
| 配置语法或范围非法、已有配置损坏/不可读、消费者不受支持/策略拒绝 | 不可信失败 | 报错，修正后才继续 |
| 发布/目录/策略/投影绑定损坏、越界、来源完整性校验不成立 | 不可信失败 | 不采纳、不披露越界内容，按原 gate 阻断 |
| 解析失败、未知状态、退出失败原因未知、只有通用 blocked 而无可信归因 | 未识别失败 | 与不可信失败相同，不推测可用性降级 |
| 用户取消 | 取消 | 未完成，无后台重试；保留先前已观察错误 |

非零退出但原因确认为入口不可用或超时，才进入相应可用性类别；未知原因不能凭退出码降级。未经允许的来源/hash 不一致与已识别过期不同：只有合同允许且可归因的相关变化才适用 degraded/source_refresh，其余完整性失败保持阻断。

## 合法零命中的唯一映射

依据 adopted architecture AD-7：先按 AD-6 完成请求、结构、完整性、权限及发布校验，并处理更高优先级的失败、过期、取消及预算状态。仅在此前置条件满足时，原始 status=insufficient_match 且 candidates=[] 唯一映射 no_match/empty；候选非空的 insufficient_match 才映射 degraded/insufficient_match。不得单凭空数组推断 no_match；未知或不一致状态仍 fail-closed。

两类均要求定向源码核查，不能证明能力不存在或绕过 required gate。原始 Locator 返回字段、status 和旧消费者语义保持不变。该规则明确未来适配器预期，不表示适配器已经实现。

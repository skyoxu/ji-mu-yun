## Protocol change

The prior blanket ban on pre-RED production entry creation prevented genuine
new modules from entering strict TDD. The new opt-in native `prepare-entry`
action creates only deterministic, declared interface scaffolding: Python
functions return None; JSON files contain empty objects. No worker-supplied
body/data or feature implementation is admitted. The contract binds the exact
plan, slice, Git HEAD and paths. All paths must be absent, planned production
owners inside the allowed write set, outside frozen/forbidden/test paths, with
no symlink or tracked-but-deleted replacement. All entries are prevalidated.
Existing inputs cannot be overwritten. The receipt is non-authorizing, and
Q2 can verify generated bytes before authoring.

Q2 remains test-only. Actual bound result assertions, nonzero CER cases and
formal expected-red are still required before Q4 can implement behavior.
No missing-import/file-existence failure, receipt, model text or scaffold can
satisfy that requirement. Local CLI and caller-session use the same native action.

The stage selector also handles Python -B, combines only compatible commands
inside frozen snapshot files, and leaves broader context commands for Q6.
File-wide markers cannot stand in for selected-node evidence. Full-file
selectors subsume duplicate node targets from that file.

- (decision) Why: realize a desktop notes prototype where one user keeps named plain-text notes available between app sessions.
- (capability) CAP-1 intent: Create a named plain-text note. Success: a note with a non-empty title can be created with plain-text content.
- (capability) CAP-2 intent: Edit a note and return to its saved content after closing the app. Success: edit and successfully save text, close and reopen the app, then reopen the note with the saved title and text intact.
- (capability) CAP-3 intent: Prevent saving a note with an empty title. Success: an empty title is rejected and no save occurs.
- (capability) CAP-4 intent: Recover from a failed save without losing unsaved edits. Success: the app reports the save failure, retains unsaved edits, and permits a retry with those edits.
- (constraint) The prototype is a single-user offline desktop app; note content is plain text.
- (decision) Non-goals: accounts, network sync, attachments, sharing and billing.

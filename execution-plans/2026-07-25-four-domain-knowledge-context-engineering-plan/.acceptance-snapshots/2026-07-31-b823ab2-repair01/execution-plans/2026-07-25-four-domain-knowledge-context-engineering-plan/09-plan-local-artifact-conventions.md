# Plan-Local Artifact Conventions

- All plan-local files use UTF-8, LF, and no BOM.
- JSON uses stable key ordering for generated snapshots and rejects `NaN` and `Infinity`.
- Paths in contracts are repository-relative with `/`; runtime absolute paths appear only in synthetic fixture payloads and are never live paths.
- SHA-256 values are lowercase 64-character hex strings.
- Inventory snapshots are generated by `tools/build_hosted_inventory.py`; no caller count is hand-entered.
- The synthetic Context Envelope reference vector is generated by `tools/build_reference_vector.py`; its test key is public fixture data and never a production secret.
- `requirements-ledger.v1.json` is machine authority for active requirement coverage; the Markdown ledger is a human-readable projection.
- `fixtures/knowledge-interface-cases.v1.json` indexes all Locator and maintenance cases; unindexed interface fixtures fail whole-directory validation.
- Locator requests use JSON stdin and results use JSON stdout at the future CLI boundary. Diagnostics belong on stderr; caller LLM hints are untrusted input.
- Maintenance fixtures use synthetic paths and hashes only. They never read `logs/phase-a-innernet/**`, fetch a remote ref, or mutate an inspected source.
- `implementation-contract.v1.json` is machine authority for slice boundaries and dependencies.
- `schemas/plan-state.v1.schema.json` and `plan-state.v1.json` are lifecycle inputs; only the plan-local validator may publish `plan-ready`.
- `95-implementation-evolution-and-completion-report.md` is append-only, non-authorizing, and excluded from normative hashes.
- `logs/knowledge-context/**` is evidence, not a source of requirements or permission.

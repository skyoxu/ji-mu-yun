P1-2 Runtime policy / conjunctive lease：⚠️ 核心算法正确，但实际控制面尚未完全接入

好的部分已经修了。

runtime policy 现在确实补齐了：

liveness
effective progress
no-progress
launch grace
terminal grace
lease
retry
backoff
status throttle
output ceiling

runtime_policy.reconcile_leases() 也真正实现了：

process_identity_matches
AND liveness_current
AND progress_current
AND no terminal

而且 heartbeat 和 Effective Progress 的独立性已有测试。

问题在 integration。

真实 bootstrap_review.py 现在只 import：

from runtime_policy import load_runtime_policy

并没有让主 lease/write-set 判定统一调用 reconcile_leases()。

真正 reviewer launch 的冲突检查依旧是：

for active in active_attempts(events).values():
    if write_set overlaps:
        reject

而 _control_plane.active_attempts() 的定义仍然只是：

attempt-reserved / attempt-started
    → active


terminal event
    → remove active

它不检查 liveness expiry，也不检查 Effective Progress expiry。

更重要的是，目前两个模块使用的 event schema 甚至不一样：

runtime_policy.py:
kind
attempt
timestamp = int

而真实 Bootstrap process events 是：

eventType
attemptId
timestamp = ISO datetime

所以现在 runtime_policy.reconcile_leases() 更像一个测试正确的平行实现，还没有成为真正 process-event authority 的消费路径。

bootstrap_review.py 确实新增了一个 policy-bound no-progress reconciliation，所以 progress expiry 比上一版好多了；但独立的 liveness_seconds 仍没有进入真实 lease occupancy 判定。

我建议只修这一处，然后停止 finding

目标非常明确：

真实 Bootstrap Process Events
        ↓
统一 runtime-policy adapter / reconciliation
        ↓
lease_occupied =
    process identity match
    AND liveness not expired
    AND effective progress not expired
    AND no terminal
        ↓
write-set occupancy / retry authorization

具体就是：

reconcile_leases() 直接消费真实 eventType / attemptId / ISO timestamp，或者增加一个唯一正式 adapter；
reviewer launch 前的 write-set overlap 不再直接把 active_attempts() 当 lease truth；
active_attempts() 最多保留为 event structural view，不能代表“lease occupied”；
heartbeat 只刷新 liveness；
Effective Progress 只刷新 progress；

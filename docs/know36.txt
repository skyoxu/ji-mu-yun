我只看到 2 个 P1，建议现在修掉，别再扩 finding。

P1-1：acceptance_mode × typed route 还没有完全闭合

当前 Spec 一方面规定这些风险必须选：

full_implementation_conformance
或
manual_pause

包括 protected path、requirements identity change、self-hosting、authority/lifecycle control 等。

但 supervised 的强制 Bootstrap trigger 列表更窄，只有：

explicit request
unresolved advisory high-risk
security/permission/data-corruption
lifecycle/authority change
independent adversarial review request

于是理论上可能出现：

mode = supervised
route = full_implementation_conformance
原因 = protected path


但 supervised trigger = false
→ 跳过 Bootstrap？

这会让 full_implementation_conformance 失去确定语义。

我建议直接固定合法矩阵：

supervised + deterministic_only + no trigger
→ maintainer decision
→ no Bootstrap


unattended + deterministic_only
→ no Bootstrap


supervised/unattended + focused_repair_verification
→ Bootstrap


supervised/unattended + full_implementation_conformance
→ Bootstrap


any mode + manual_pause
→ stop / non-authorizing

并规定：

任何 registered Bootstrap trigger 都必须使 route 至少升级到 full_implementation_conformance 或 manual_pause。

这样 mode 确实是正交维度，但不会改变 typed route 的语义。

P1-2：maintainer supervised decision 绑定得太少

现在 contract 只要求：

mode
candidate
decision
owner
policy_identity
authorizes

问题是，同一个 candidate 下，如果：

Consumer Closure 变化
required-check set/result 变化
route 变化
authority selection 变化
policy 变化

旧 maintainer decision 理论上仍可能被拿来复用。

而 Architecture 自己已经要求 finalization exact-match candidate、closure、required checks、mode、route。

所以 supervised decision 至少应该绑定：

baseline_identity
candidate_identity
consumer_closure_identity
required_checks_identity
acceptance_mode_identity
route_identity
policy_identity
authority/spec-selection identity

Web Sol 的聊天内容仍然不需要绑定进去。这个 artifact 表达的是：

maintainer 对这一套被冻结的机器状态完成了 supervised semantic review。

不是“某个模型说 PASS”。

一个非阻塞瘦身项

我会把 docs/know35.txt 从 Canonical Spec role graph 的 provenance 里移出去。

现在它进入了 canonical selection 和 source-freeze，所以一份讨论记录也成了 package identity 的组成部分。

技术上不一定错，但跟你现在追求的“轻量 supervised workflow”方向相反。更干净的是：

know35
→ 作为历史输入 / memlog 记录
→ 内容已经吸收到 Spec + Architecture
→ 不进入最终 Canonical Package role graph

PRD / addendum 保留正式 provenance 就够了。

其他部分我认为做得对

新的 VDD 已把 ARBE-021/022、A42–A46 纳入计划，S3 负责 mode/route/trigger，S5 负责 supervised decision 或 Bootstrap evidence 的 finalization；command registry 也对应更新了。

而且上次指出的 freshness 问题已经修了：validate_all 现在会真正调用 source-freeze validation、Skill Input validation 和 knowledge preflight，不再只是比较硬编码 hash。

还有一个决定我赞成保留：

这次改动本身修改 Acceptance/Bootstrap authority control，因此它自己的最终验收仍强制 Bootstrap。

这是很合理的一次 dogfood；等这次能力自身通过后，以后的普通 supervised 工作才享受 fast-path。

结论：设计已经基本对了。修上面两个 P1 后，就不要继续做 VDD/Spec finding，直接 maintainer authorization → Quick Dev 实现。 实现后你再推 GitHub，我建议下一轮我们直接按 production code 检查 supervised fast-path 是否真的生效，而不是再审状态文档。

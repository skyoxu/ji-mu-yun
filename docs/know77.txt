## 4.1 修复 observation contract

实现以下契约：

1. `observed_failure_ids` 由 runner、recorder、parser、composer 使用同一 schema。
2. RED 必须记录非零 exit code 和精确匹配的 failure IDs。
3. GREEN/REFACTOR 不得携带非空 RED failure IDs。
4. parser 接受声明的可选字段，但拒绝其他未知字段。
5. 新鲜 lifecycle 必须能够走到 `LifecycleRunner.close()`，不能再出现 `stage observation shape is invalid`。
6. 如果字段语义改变，发布 schema v2；v1 历史证据只能读取，禁止原地重写。

新增测试至少覆盖：

* 合法 RED observation
* RED failure ID 缺失、重复、额外、错误
* GREEN 携带 RED failure ID
* 未知字段
* v1 只读兼容
* 完整 RED→GREEN→REFACTOR→close

## 4.2 分离 input snapshot 与真实 changed paths

不要再把 `execution_snapshot_paths` 当作 changed files。

实现：

1. persistent loop 传递全部 `execution_snapshot_paths`，不得只取 `[0]`。
2. snapshot 是只读输入绑定；changed paths 必须由 RED baseline 与当前 candidate 的真实字节差异产生。
3. before/after 字节相同的文件不得出现在 diff 中。
4. 创建、修改、删除都必须被识别。
5. 实施阶段写入但未列入 snapshot 的文件仍必须被检测。
6. adapter 自己的 run-local evidence 只能通过明确的 adapter-owned boundary 排除，不能用宽泛 `logs/**` 漏掉业务越界写入。
7. diff manifest 必须绑定实际 before/after hash，不能依赖 backend 自报 changed files。

新增测试：

* 两个以上 snapshot 都被绑定
* no-op 不生成 diff
* snapshot 外合法生产修改可见
* undeclared file creation 被发现
* deletion 被发现
* forbidden write 被拒绝
* unrelated write 被拒绝
* 已存在脏文件的 before/after continuity 不被吞掉

## 4.3 强制写边界

4. `planned_new_files` 必须属于 allowed write set。

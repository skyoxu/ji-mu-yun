D1-D9 全部冻结，但按以下最终修正版执行。

D1. Current Identity Envelope And Domain Contract
采用建议 envelope：

sha256(canonical_bytes({
  "domain": owner_domain,
  "payload": semantic_projection
}))

新 artifact / receipt 必须显式携带：
- canonical_evidence_version
- identity_domain
- content_identity

identity_domain 采用建议 regex：

^[a-z0-9]+(?:[._-][a-z0-9]+)*\.v[1-9][0-9]*$

补充不变量：

1. artifact schema/version 必须静态映射唯一 primitive version + domain。
2. validator 顺序：
   schema/version
   → expected primitive/domain
   → carried metadata equality
   → semantic projection validation
   → canonical/hash replay
   → digest equality。
3. primitive version 不进入现有 hash envelope，以保持 brownfield domain-separated digest compatibility。
4. 因此必须区分：
   - content digest
   - complete identity contract

   canonical algorithm version 改变时，complete identity contract 必须变化；
   但若新算法与旧算法产生完全相同 canonical bytes，不要求仅为了 version metadata 人为改变历史 digest。
5. 若算法语义发生不兼容改变，artifact owner 必须显式升级 schema/version，并在需要时升级 domain/projection version；禁止旧 schema 静默切换算法。
6. domain/projection 改变自然产生新的 content digest。
7. metadata 本身不授予 authority。

D2. Artifact DAG Custody And Mutation Rule
按建议全部固定。

Artifact immutable；
repair/rerun/reprojection 产生 successor；
current pointer 只能是 owner-scoped selection artifact；
禁止 central mutable evidence registry；
pointer 变化不改变 immutable artifact truth。

允许 deterministic reproduction 得到相同 content identity，但不得原地改写已发布 bytes。

D3. Consumer Closure Typed Edge Taxonomy
采用建议 taxonomy，但增加时序边界：

Pre-execution Consumer Closure fixed-point 的核心 edge types：

- changed_artifact
- implementation_contract
- requirement_acceptance_binding
- executable_entrypoint
- validator_or_consumer
- repository_authority
- authorization_prerequisite
- external_selection

tests / fixtures 可作为 validator_or_consumer 的 typed subtype，不允许退化为自由文本。

`deterministic_evidence` 不得作为生成 Consumer Closure fixed-point 的反向依赖，否则会形成：

closure
→ required-check execution
→ deterministic evidence
→ closure

的循环。

deterministic evidence 应作为 closure identity 冻结之后生成的 downstream evidence artifact；
当 Bootstrap review-input DAG 需要消费它时，可以使用 typed `deterministic_evidence` attachment edge，但它不参与原 Consumer Closure completeness fixed-point。

每条 edge 仍必须绑定 source identity、target identity、edge type、discovery basis、validation result。

D4. Model-Visible Range Projection
采用 raw-file-bytes identity 和 byte-coordinate 方案，但必须保持 Canonical Spec 已冻结的完整 Projection obligation。

坐标固定为：

zero-based
start-inclusive
end-inclusive

不要改成 end-exclusive，因为当前 Canonical Spec 已冻结 inclusive range 语义；Architecture 不应静默改变 requirement authority。

Range Projection descriptor 至少绑定：

- repository-relative source path
- raw source/full-source content hash
- zero-based inclusive start byte
- zero-based inclusive end byte
- exact projected/extracted bytes hash
- encoding
- projection version
- inclusion reason
- applicable changed-set / requirement / acceptance binding，或等价的 hash-bound projection-context identity

规则：

- source identity 基于原始 bytes
- 不 newline normalize
- 不 Unicode normalize
- 不 replacement decode
- range 必须落在完整合法字符边界
- source identity 改变后旧 descriptor stale
- reviewer 不得自行选择 range
- threshold/budget 不进入 Architecture invariant，继续归 model-visible runtime policy

注意：
raw file content hash 与 canonical JSON artifact identity 是不同层次，不要强行把 arbitrary file bytes 塞进 canonical JSON value model。

D5. Canonical Bootstrap Segment Descriptor
采用建议字段集和 domain：

jimuyun.bootstrap.segment-descriptor.v1

但必须修正 attempt 绑定：

`parent attempt identity` 不进入 canonical Segment Descriptor identity。

原因：
Canonical Spec 已要求同一个 segment 在普通 transport retry 时保持同一个 descriptor identity；
而每次 retry 必须有新的 attempt identity。
若 attempt identity 是 descriptor 字段，会造成自相矛盾。

最终分层：

Stable Segment Descriptor binds:
- review run identity
- baseline/current identities
- Changed-set Manifest identity
- Consumer Closure identity
- route/profile identity
- reviewer role
- assigned artifact/path/range identities
- requirement/acceptance bindings
- required-check evidence identities
- segment ordinal / total
- output/evidence contract
- predecessor/repair input when semantically applicable
- model identity only where cache/reuse contract explicitly requires it

Attempt Request / Attempt Event binds:
- unique attempt identity
- Segment Descriptor identity
- access-proof / launch authorization identity
- executable/model execution route
- process identity

普通 transport retry：
same Segment Descriptor
+ new attempt identity

context-budget repartition：
new segment partition
→ new Segment Descriptor identity

assignment、request semantic payload、child receipt、parent validator、coverage fold、retry/cache 必须使用同一个 canonical segment projection contract。

D6. Required-Check Execution And Reuse Receipt
按建议全部固定。

补充强调：
receipt 必须引用真实 command-registry contract / runner identity；
通用 receipt validator 不能替代真实 runner execution。

Reuse 只能 exact-match。
required-check receipt 始终 authorizes=[]。

D7. Bootstrap Runtime Policy, Event And Lease
采用 versioned runtime-policy + Event-Sourced State Machine，但明确区分：

Liveness != Effective Progress != Lease truth。

固定：

1. Process Event 是 execution-fact authority。
2. Lease 是 events + current process identity + runtime policy 推导的 derived view。
3. heartbeat 只能证明 liveness。
4. heartbeat 可以使控制器在 no-progress ceiling 尚未达到时继续认为活进程仍占有其 write-set；
   但 heartbeat 绝不能：
   - 刷新 Effective Progress timestamp
   - 重置 no-progress deadline
   - 延长 no-progress stop-loss
   - 单独证明 completion
5. 只有 controller-validated Effective Progress Event 可以刷新 no-progress window。
6. 即使 heartbeat 持续正常，一旦 effective-progress window 超过 policy ceiling：
   - 停止新增 reviewer/model calls
   - terminate/isolate active child
   - append terminal/stale/failed process event
   - reconcile lease
   - produce typed non-authorizing recovery result
7. retry reservation 必须发生在 terminal observation + reconciliation 之后。
8. 每次 retry 使用新 attempt identity，不覆盖旧 event/receipt。
9. timeout、heartbeat interval、no-progress ceiling、terminal grace、retry ceilings、backoff、liveness/lease TTL 等具体数值均归 versioned runtime policy，不进入 Architecture Spine 常量。

不要采用“heartbeat 能无限续 lease”的语义；
也不要采用“只有 Effective Progress 才能证明进程仍活着”的语义。
两者必须分层。

D8. Terminal Taxonomy And vcec-r1n
按建议固定：

- completed
- failed-transport
- stale-process
- blocked-recovery-required
- abandoned

这些全部是 Bootstrap execution terminal/classification，不是 lifecycle state。

vcec-r1n 固定：

terminal = abandoned
classification = historical-runtime-failure
reusable = false
authorizes = []

其内部历史 attempt 仍保留各自 failed/stale/transport evidence；
不得删除、重写或升级为成功。

D9. Brownfield Migration Sequence
采用建议方向，但调整为无验证空窗的最终顺序：

   在任何 mandatory consumer cutover 前，legacy replay capability 必须已经存在。

   证明 shared primitive 与现有 bytes/hash 完全兼容。

4. 将这些 domain-separated producers/validators 切换到 shared primitive。

5. 对 domainless producers 发布新的 owner schema/domain/version；
   历史 artifact 保持 immutable，只通过 legacy verify-only profile 验证。

6. 切换所有 mandatory consumers：
   bmad-spec、VDD、exact-cover、Acceptance、Bootstrap，

   - current vectors
   - legacy vectors
   - cross-rejection
   - unknown-version
   - wrong-domain

   才删除各 Skill 内重复 canonical JSON/hash/path-normalization implementation。

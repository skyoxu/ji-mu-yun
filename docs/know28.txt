同意，按这个物理边界和 API 方向固定。

Architecture 决定：

Shared Canonical Evidence Primitive 的 repo-owned 物理位置为：

scripts/toolchain/canonical_evidence/

它属于 repository shared infrastructure，不属于任何单一 Skill，也不放入可能与安装器/生成内容混淆的 _bmad 路径。

对外保持稳定的小接口：

- canonical_bytes(value)
- domain_hash(domain, projection)
- normalize_repository_path(root, path)
- validate_content_identity(domain, projection, expected)
- golden-vector / mutation runner

同时固定以下边界：

1. 单向依赖
   bmad-spec、VDD、exact-cover、Quick Dev、Acceptance、Bootstrap 可以依赖 canonical_evidence；
   canonical_evidence 禁止反向 import 任何业务 Skill 或 lifecycle owner。

2. Shared primitive 只拥有 algorithmic identity mechanics，不拥有 evidence semantics。
   它不得拥有：
   - artifact schema
   - lifecycle state
   - payload projection
   - producer/publisher authority
   - route/finalization
   - central evidence registry
   - mutable runtime state

3. Artifact-specific domain constants 留在各 owner。
   不建立中央业务 domain registry。
   owner 负责构造 semantic projection 和声明 domain，
   shared primitive 只负责 canonicalize/hash/validate。

   固定调用方向：

   owner semantic projection
   → canonical_bytes
   → domain_hash
   → content identity

4. normalize_repository_path 只负责 repository identity normalization。
   它可以规范为 canonical repository-relative representation，并拒绝 root escape；
   但不得决定：
   - 是否属于 changed-set
   - 是否进入 Consumer Closure
   - 是否属于 repository authority
   - reviewer 是否可读
   - write-set/scope 是否允许

   filesystem containment、symlink/reparse/junction 等运行时安全语义如需额外处理，应与纯 path identity normalization 分层定义。

5. Canonical encoding 必须 fail-closed，并由 Architecture 明确：
   - 支持的 value type
   - object key ordering
   - UTF-8 规则
   - Unicode normalization policy
   - integer/number 表达
   - float 是否允许
   - duplicate-key rejection
   - newline/serialization 规则
   - unsupported value 的拒绝行为

6. Shared primitive 必须有可绑定的算法版本/identity，
   例如 CANONICAL_EVIDENCE_VERSION 或 primitive_identity()，
   使 receipt 能证明使用的是哪一版 canonical algorithm。
   该版本只代表算法实现，不代表 lifecycle authority。

7. Shared golden vectors 放在 canonical_evidence package 内，覆盖：
   - canonical encoding
   - domain separation
   - path normalization
   - content identity validation
   - mutation rejection

8. Artifact-specific mutation/golden tests 继续归各 owner。
   例如 Bootstrap Segment Descriptor、Acceptance Consumer Closure、VDD source-freeze 的语义 mutation 不迁入 shared primitive；
   它们只复用 shared canonical primitives。

9. 禁止各 Skill 再维护私有 canonical JSON/hash/path-normalization 实现。
   Brownfield 迁移应识别 bmad-spec、VDD、exact-cover、Acceptance、Bootstrap 当前重复实现，并逐步切换到 shared package。
   迁移过程中必须用跨消费者 golden vectors 证明兼容性，任何 identity 漂移 fail closed。

请将这个决定记录为 Architecture decision，并继续分析 Brownfield migration points；不要改变现有 artifact ownership 和 lifecycle authority。

## 3. 修复策略

### 3.1 不允许生命周期倒退

当前工具链计划已经声明：

```text

```

不要把 `plan-state.v1.json` 强行改回 `draft` 或 `plan-ready`。静态生命周期没有反向转换。

正确方式是在原目录追加一个 prestart repair round：

```text

```

在 repair round 未关闭期间，通过 plan-local entry validator 阻止执行。修复完成后：

1. VDD 生成 `plan-ready-revalidated` receipt，但不发布新的生命周期状态；
2. maintainer 发布新的 implementation authorization successor；
3. `plan-state` 继续保持 `implementation-authorized`；
4. 新 authorization successor 明确 supersede 2050 的旧授权。

`2050ec68` 已经提前修改以下共享文件：


后续对 Quick Dev 入场门禁所必需的最小共享代码修复，也必须进入同一个 bootstrap delta，并使用 regression 验证。不得趁机实现 W0-W6 的目标行为。

### 3.3 使用当前 v1 作为 bootstrap，不冒充未来 v2

W0-W4 尚未实现真正的 Skill Input v2。当前：


- 保留原文件作为历史证据；
- 在 disposition 中标记 `historical-interim-noncanonical`；
- 从当前 authorization 输入中移除它；
- Quick Dev 入场暂时使用仓库现有 canonical v1 execute contract、paged snapshot、typed semantic child 和 ready validator；

我读了最新 `main`。当前 HEAD 是 `d9bec07def3f19e6da3d4672d671819954a9c470`，提交信息是 `Harden bootstrap review operability and TDD execution`。

先说判断：**BROH 的主体方向已经落地，但我现在不能判定它“完全符合之前要求”**。Bootstrap 的并发/停止规则、Quick Dev terminal predicate、Acceptance 后续路由这些主体都已经有了；问题集中在 **BROH-S4：Acceptance 自主决定是否需要 Bootstrap 这部分只完成了一半**。

### 对 BROH 当前状态的判断

已经符合的部分比较明确。BROH requirements 已经扩展到 `BROH-001..024`，其中明确要求 Acceptance-owned decision、deterministic-only、并发 discovery、P2 current-run closure、P0/P1 focused verifier、zero-finding clean、semantic stop rule 等。 95 报告也记录 S0–S7 最终通过 `implementation-complete`，并把 Bootstrap、Acceptance 和 plan-local consumer suites 纳入 terminal closure。

而且现在 Acceptance 后半段的路由已经相当好：

```text
not_required
→ deterministic_only

required + 0 rounds
→ full_implementation_conformance

Round 1 P0/P1 repaired + no escalation
→ focused_repair_verification

later novel P0/P1 / authority change / high-risk boundary change
→ full discovery proposal

3 rounds
→ manual_pause
```

这已经写进 `project_bounded_review_route()`。 Acceptance Skill 本身也明确声明拥有 complete coordination loop，并按 typed `nextAction` 调用 Bootstrap，再 import 结果继续 Acceptance。

所以**“Acceptance 调度 Bootstrap”现在基本已经具备**。

但“Acceptance 自主决定要不要 Bootstrap”还有下面几个实质问题。

第一，`decide_bootstrap_command()` 现在仍接受两种输入：

```python
request = _read_json(request_path)
decision = request

if reviewInputs:
    decision = decide_review_requirement(reviewInputs)
```

也就是说，如果 caller 不传 `reviewInputs`，仍然可以直接提交一个已经写好的：

```text
requirement = required / not_required
requirementSources = [...]
```

然后 Acceptance 会把它发布。

这意味着 **caller-authored decision 仍然没有真正被封死**。

第二，即使走新的 `reviewInputs`，当前 `review_requirement.py` 仍然让 caller 提供这些关键事实：

```text
candidate.workflowControlPlaneChange
protectedFacts.highRiskBoundary
deterministicEvidence.status
maintainerIntent
```

Acceptance 只是根据这些布尔值做决定，没有自己从 candidate manifest、changed paths、repo rules、protected-path policy 等推导它们。

所以理论上 caller 可以给：

```text
changedPaths =
  .agents/skills/run-phase-bootstrap-review/SKILL.md

workflowControlPlaneChange = false
highRiskBoundary = false
```

那么当前 producer 可以得到 `not_required`。

测试现在证明的只是：

> caller 写 `callerRequirement=not_required` 不能覆盖 `workflowControlPlaneChange=true`。

它没有证明：

> caller 无法伪造 `workflowControlPlaneChange` 本身。

第三，BROH-009 要求 closed、hash-bound trigger policy，并且 unknown/contradictory facts fail closed。当前 producer 实际只认识：

```text
workflow-control-plane-change
protected-high-risk-boundary
explicit-maintainer-request
deterministic-facts-incomplete
deterministic-low-risk
```

而且没有真正的 repository-owned trigger-policy artifact；未知字段基本会被忽略。

第四，有一个很直接的 contract bug：新 schema 规定：

```text
decisionVersion = v6
```

而 producer 实际输出：

```text
decisionVersion = v9
```

第五，现在所有 `required` decision 都被映射成：

```text
bootstrap-implementation-conformance
```

即使是：

```text
workflowControlPlaneChange = true
```

也是如此。

同时 Acceptance 当前的 scope builder 也是硬编码 `bootstrap-implementation-conformance`。

这比我们之前设计的“Skill/control-plane 变更 → `bootstrap-skill-route`”弱了一层。它不一定违反 BROH-A23 的最窄解释，但**没有实现我们之前想要的 risk-specific profile selection**。

最后还有一个治理一致性问题：95 报告已经声明 implementation-complete，但 `plan-state.v1.json` 仍是 `implementation-authorized`，S0–S7 都是 pending；`resume-state.v1.json` 也还让下一步从 S0 开始。

这不一定代表 terminal evidence 无效，但**目录的 lifecycle projection 已经明显滞后于实际 execution evidence**。另外当前 HEAD 没有 GitHub commit status/check，所以我能确认的是 repo artifacts 和 95 中记录的本地 validation，不能把它说成有独立 CI 佐证。

因此我的结论是：

> **BROH 的 Bootstrap/Quick Dev/后半段 Acceptance routing 基本达到目标；Acceptance 自主 risk decision 还不能算完成。**

而且这不是应该另起一个新 plan 的新需求——**BROH-008/009/012 本来就要求它**。所以我建议先把它作为当前 BROH 的 implementation repair 收掉，再做 Acceptance。

下面是我建议的修复方案。

# Acceptance 自主 Bootstrap 决策权收口方案

## 1. 目标

把当前：

```text
Caller
  ↓
提供 risk facts / 甚至直接提供 required|not_required
  ↓
Acceptance 验证并路由
```

改成：

```text
Caller
  ↓
只提供 target/candidate/evidence 的不可变引用
  ↓
Acceptance 自己读取并验证当前仓库事实
  ↓
Acceptance 自己生成 risk facts
  ↓
Acceptance 自己计算 review requirement
  ↓
Acceptance 自己选择 Bootstrap profile / lens
  ↓
Acceptance route-acceptance
```

最终原则：

```text
Caller describes identity.
Acceptance derives facts.
Policy classifies risk.
Acceptance decides assurance.
Bootstrap executes assurance.
```

Caller 永远不能直接决定：

```text
required / not_required
risk category
Bootstrap profile
reasonCodes
workflowControlPlaneChange
highRiskBoundary
```

# 4. 新增 Acceptance-owned Current Fact Projection

当前 `review_requirement.py` 不应该直接接受：

```json
{
  "workflowControlPlaneChange": true,
  "highRiskBoundary": false
}
```

这种 caller-authored semantic fact。

建议产生新的中间 artifact：

`acceptance-semantic-review-facts.v1`

它必须由 Acceptance 从当前 bytes 自己构造。

输入只允许是引用，例如：

```text
repositoryRoot
targetPlan
preparedAcceptanceRunInput
implementationContract
deterministicEvidenceRefs
maintainerIntent
```

其中：

`maintainerIntent` 只能是 upgrade：

```text
default
request_semantic_review
```

不能存在：

```text
skip_review
force_not_required
```

---

# 5. Candidate facts 必须由 Acceptance 自己重放

直接复用当前已经很强的：

```text
load_current_candidate_identity()
```

它已经可以验证：

```text
baseline manifest
candidate manifest
changed paths
candidate custody
knowledge context
content hashes
deleted/present bindings
```

因此 risk producer 应消费这个 current identity，而不是让 caller 再写一遍：

```text
changedPaths
candidateHash
workflowControlPlaneChange
```

基本结构：

```text
prepared-run-input
      ↓
load_current_candidate_identity
      ↓
candidateIdentity
      ↓
derive_semantic_review_facts
```

任何 candidate bytes 变化：

```text
→ old facts stale
→ old decision stale
→ 必须重新 derive
```

# 6. 创建 repository-owned Closed Trigger Policy

建议在 Acceptance Skill 内增加一个真正的 policy artifact，例如：

`references/semantic-review-trigger-policy.v1.json`

这是新文件建议，不声称当前存在。

它应该是 authority input，而不是 caller input。

建议 hard-trigger enum：

```text
workflow_control_plane_changed

lifecycle_authority_changed

protected_path_changed

security_or_permission_boundary_changed

shared_execution_entrypoint_changed

public_api_contract_changed

database_schema_or_migration_changed

runtime_or_deployment_boundary_changed

destructive_or_irreversible_change

deterministic_evidence_incomplete

unresolved_acceptance_blocker

explicit_maintainer_review_request
```

不得接受自由文本 reason。

Policy 自身进入：

```text
policyHash
```

并写入 decision。

修改 policy bytes：

```text
→ decision invalid
```

---

# 7. Hard trigger 的事实必须可证明

例如：

## workflow_control_plane_changed

从 changed paths + repository-owned path classification 得出：

```text
.agents/skills/vdd-execution-plan/**
.agents/skills/quick-dev-tdd-adapter/**
.agents/skills/run-refactor-implementation-acceptance/**
.agents/skills/run-phase-bootstrap-review/**
shared workflow launchers
controlling validators
```

不是：

```text
caller says true
```

## protected_path_changed

由当前 repository protected-path authority 决定。

## security_or_permission_boundary_changed

来自当前 plan/contract + changed-path classification + Acceptance deterministic evidence。

## database_schema_or_migration_changed

由实际 changed paths / registered contracts 识别。

如果某个风险事实需要额外 authority 才能确定：

```text
unknown
```

必须：

```text
decisionStatus = blocked
```

而不是：

```text
not_required
```

# 8. 不要把“缺 deterministic evidence”变成 semantic review

当前代码把：

```text
deterministicEvidence.status != passed
```

转成：

```text
required
```

我建议改掉。

应该：

```text
deterministic evidence incomplete
→ blocked
```

因为 Bootstrap 不应该替机器验证补课。

正确顺序：

```text

  ├─ no  → blocked / repair evidence

```

只有确定性事实完整之后才允许：

```text

not_required
```

# 9. Decision contract 建议变成三态控制

建议 decision 增加：

```text

  ready
  blocked
```


才允许：

```text

  required
  not_required
```

```text

```

例如：


全部：

```text

```

# 10. Caller 不能再直接提交 decision

当前：

```text
decide_bootstrap_command()
```

存在：

```text
decision = request
```

的 compatibility fallback。

这个通路必须从“current write path”移除。

新的 `decide-bootstrap` 只接受：

```text
Acceptance-owned fact derivation request
```

不得接受：

```text

reasonCodes
profile
risk flags
```

作为 caller input。

如果历史 evidence 确实需要兼容，可建立明确的：

```text

```

其能力只能是：

```text
read
replay historical evidence
explain
```

它不能：

```text
publish current decision
route current candidate
authorize Bootstrap
satisfy exact reuse
```

即：

```text
legacy-read
current-write-prohibited
```

# 22. Definition of Done

只有下面全部成立，才能说：

> Acceptance 已经真正拥有 Bootstrap 自主决策权。

```text
Caller cannot author required/not_required.

Caller cannot author semantic risk booleans.

Acceptance derives current facts from repository-bound evidence.

Closed policy deterministically classifies those facts.

Incomplete/unknown facts block instead of silently downgrading.

Acceptance alone selects required/not_required.

Acceptance alone selects Bootstrap profile/lens.

not_required produces deterministic_only with zero semantic execution.

required produces a typed Bootstrap route.

Bootstrap alone retains semantic execution authority.

Every decision is bound to current candidate, policy,
deterministic evidence, knowledge and authority bytes.

Legacy decisions are read-only compatibility evidence.

Current route rejects handwritten/stale decisions.

Profile-incompatible exact reuse is impossible.

Existing bounded Round/P2/focused-verifier semantics remain unchanged.
```

最终职责模型：

```text
VDD
  → plan intent

Readiness Skill
  → pre-implementation plan sanity

Quick Dev
  → implementation

Acceptance
  → deterministic truth
  → semantic-risk classification
  → Bootstrap requirement decision
  → Bootstrap route scheduling
  → final acceptance

Bootstrap
  → semantic assurance execution only
```

我的建议是：**先不要开始新的 Readiness Skill 实施。先把这个 BROH repair 收干净并跑一次真实 Acceptance。** 因为现在已经非常接近正确架构，缺的是 Acceptance decision ownership 的最后一道“防 caller 注入”边界，而不是再设计一套新的 Review 系统。

等这个 repair 通过后，你的实施后链路基本就真正定型了。

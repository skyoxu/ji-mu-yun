1. 草案降级后，部分承重能力没有被提取

这是当前最重要的问题。

PRD addendum 明确要求 VDD 为每个 slice 确定性生成：

{
  "slice_id": "S...",
  "requirement_ids": [],
  "obligation_ids": [],
  "acceptance_ids": [],
  "source_refs": [],
  "contracts": [],
  "allowed_paths": [],
  "forbidden_paths": [],
  "selector_intents": [],
  "validation_commands": []
}

但当前所有 normative Spec 文件中都没有 agent-context.json 的生成合同、schema 和缺失字段判定。

此外，原草案 §§15–17 要求 Spec 提供的以下内容也没有完整提取：

compile_plan.py、quick_dev/run.py 的稳定接口；
--resume-from first-failed-stage；
完整 Q0–Q8 状态转换表和禁止跳转；
全部 machine-readable schema；
slice hard-split/merge 与稳定 ID 算法；
selector semantic identity 算法；
failure fingerprint 及分类优先级；
exact-cover、invalidation traversal、terminal predicate 伪代码；
detached failure-family / mutation matrix；
semantic worker 的 context limit、timeout、conflict protocol。

因为原草案现在只是 provenance，Architecture 默认不能再把这些内容当规范合同，所以它们不能继续留在那里。

2. Assertion edge schema 仍不满足 FR-15/CAP-7

当前 schema-contracts.md 只有：

{
  "acceptance_id": "...",
  "assertion_id": "...",
  "selector_identity": "...",
  "stage": "...",
  "run_id": "...",
  "result_ref": "...",
  "result_sha256": "...",
  "observed": true,
  "derived_by": "deterministic-validator"
}

至少还缺少：

plan_id/plan_hash
slice_id
candidate_hash
observation_id
validator/producer 的可绑定 identity
assertion 的实际结果或 expected/actual outcome
必要的 target/fixture/case-source 绑定或其 receipt 引用

PRD FR-15 明确要求 candidate、artifact、run、selector identity 能重读匹配。当前 edge 无法单独证明它属于当前 candidate lineage。

同意，将 parse_json_strict(raw) 加入 Shared Canonical Evidence Primitive 的稳定 API，并将其作为 repository-canonical-json.v1 的必要入口。

Architecture 固定：

raw JSON bytes
→ parse_json_strict(raw)
→ validated canonical value model
→ canonical_bytes(value)
→ domain_hash(domain, projection)

原因：
duplicate key 在普通 JSON parser 转成 object 后已经不可恢复，因此 duplicate-key rejection 必须发生在 shared primitive 的 raw parse boundary，不能委托给各 artifact owner。

repository-canonical-json.v1 固定以下合同：

1. 支持的 canonical value types：
   - null
   - boolean
   - UTF-8 string
   - signed 64-bit integer
   - array
   - string-keyed object

2. 明确禁止：
   - float
   - NaN / Infinity
   - bytes
   - Path
   - tuple
   - set
   - custom object
   - 超出 signed 64-bit 范围的 integer

   任一 unsupported value 必须 fail closed。

3. parse_json_strict(raw)：
   - 以 raw bytes 为 authoritative input
   - 只接受合法 UTF-8
   - 拒绝 UTF-8 BOM
   - duplicate object key 必须 fail closed
   - 拒绝 lone surrogate / 非 Unicode scalar value
   - JSON number 只允许可表示为 signed 64-bit integer 的整数
   - float/exponent/fractional number 均拒绝
   - 不允许 parser-specific coercion

4. Unicode：
   - 不自动执行 NFC/NFD 或其他 normalization
   - 精确保留解析后的 Unicode scalar sequence
   - object key 按 Unicode scalar sequence lexicographically 排序
   - 视觉等价但 code point 不同的字符串必须保持不同 identity

5. canonical_bytes(value)：
   - 只接受已经属于 canonical value model 的值
   - UTF-8
   - 无 BOM
   - compact serialization
   - 无 trailing newline
   - deterministic object-key ordering
   - unsupported host-language type fail closed

6. Architecture 还必须明确唯一 canonical string escaping rule：
   - quote / backslash / control characters 的编码
   - 非 ASCII Unicode scalar 的输出形式
   - 禁止存在两种 byte-equivalent semantic serialization

   所有消费者必须复用同一个 shared serializer，禁止依赖各语言/Skill 默认 JSON serializer。

7. parse_json_strict 与 canonical_bytes 的职责不能混淆：
   - parse_json_strict 负责 raw syntax / encoding / duplicate-key / numeric-domain validation
   - canonical_bytes 负责 canonical value → deterministic bytes
   - artifact owner 负责 artifact-specific schema 与 semantic projection

8. Stable API 更新为：
   - parse_json_strict(raw)
   - canonical_bytes(value)
   - domain_hash(domain, projection)
   - normalize_repository_path(root, path)
   - validate_content_identity(domain, projection, expected)
   - golden-vector / mutation runner

9. Golden vectors 必须新增：
   - duplicate keys
   - UTF-8 BOM
   - invalid UTF-8
   - lone surrogate
   - NFC/NFD distinct identities
   - min/max int64
   - int64 overflow
   - fraction/exponent/negative zero number forms
   - key ordering
   - escaping cases
   - trailing newline
   - unsupported host-language types

核心不变量：

Raw JSON validity is decided before value construction.
Canonicalization never attempts to recover information already lost by a permissive parser.
Duplicate-key rejection is shared infrastructure, not artifact-owner responsibility.

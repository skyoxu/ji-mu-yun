P1-1：修正 D1 identity mapping 粒度

原来的：

artifact schema/version
→ unique primitive version + domain

粒度过粗。

最终固定为：

artifact schema/version
+ identity field/purpose
→ unique canonical primitive version
+ identity domain
+ semantic projection contract

原因：
同一个 artifact schema 内允许存在多个不同语义用途的 identity，例如：
- closure identity
- binding identity
- candidate identity
- receipt identity
- projection identity

这些 identity purpose 可以共享 primitive version，但不得因此被迫共享 domain 或 semantic projection。

Architecture 必须定义稳定的 identity_purpose，并由 artifact owner schema/version 静态绑定。

完整机器 identity reference 固定至少包含：

{
  "schema_version": "...",
  "identity_purpose": "...",
  "canonical_evidence_version": "...",
  "identity_domain": "...",
  "content_identity": "sha256:..."
}

其中：

content_identity 只是 digest，不是完整 identity reference。

Consumer 做 identity equality / binding / reuse 判断时，必须比较完整 identity reference；
禁止仅因为 sha256 digest 字符串相同就认为两个不同 purpose/domain/version 的 identity 等价。

Validator dispatch 固定为：

schema_version
+ identity_purpose
→ expected primitive version
+ expected domain
+ expected semantic projection contract
→ verify carried metadata
→ build/validate projection
→ canonicalize/hash
→ compare content_identity

调用者不得自行指定 identity purpose 对应的 domain/version/projection。

Brownfield digest compatibility 继续保持：
primitive version metadata 不加入当前 domain hash envelope。
因此旧的正确 domain-separated digest 不需要仅为了增加 version metadata而重签；
但 current consumer 比较的是完整 identity reference，而不是裸 digest。


P1-2：闭合 D7 lease occupied 的确定性公式

Architecture 固定 derived lease view：

lease_occupied =
  current_process_identity_matches
  AND liveness_not_expired
  AND effective_progress_window_not_expired
  AND no_terminal_event

其中：

1. current_process_identity_matches
   至少绑定：
   - PID
   - process creation identity

   不能只比较 PID。

2. heartbeat 只刷新 liveness window。

3. Effective Progress Event 只刷新 effective-progress / no-progress window。

4. heartbeat 永远不能：
   - 刷新 Effective Progress
   - 重置 no-progress deadline
   - 延长 no-progress stop-loss
   - 证明 completion

5. Effective Progress 也不能替代 process liveness。

6. 任一条件失效：
   - process identity mismatch
   - liveness expired
   - effective-progress window expired
   - terminal event exists

   都必须进入 reconciliation，而不是继续把 lease 当作 occupied truth。

7. reconciliation 根据：
   - Process Events
   - current process identity
   - current runtime policy

   决定 terminalize / stale / retry-eligible / abandon 等下一状态。

8. Lease 始终只是 derived view。
   Process Events + current process identity 才是恢复 authority。

这避免实现者自行采用 heartbeat/progress 的 OR、AND 或隐式续租规则。


P1-3：拆分 D8 attempt terminal 与 segment/run outcome

原来的单层 taxonomy 不够准确，因为 transport/stale attempt 可能继续 retry。

Architecture 改为两层：

A. Attempt Terminal Classification

- completed
- failed-transport
- stale-process
- abandoned

每一个 attempt 都是 immutable execution attempt。
attempt terminal 后不得覆盖其 events/receipt。

B. Segment / Run Outcome

- completed
- blocked-recovery-required
- abandoned

Attempt terminal 必须经过：

attempt terminal
→ process/lease reconciliation
→ retry policy evaluation
→ receipt/coverage fold
→ segment/run outcome

因此：

failed-transport
或
stale-process

不能自动等价为整个 segment/run terminal。

例如：

failed-transport
→ reconciliation
→ retry eligible
→ new attempt identity
→ same stable Segment Descriptor

达到 retry ceiling 或无法安全恢复后才可能折叠为：

blocked-recovery-required

对于 context-budget：

attempt failed
→ repartition required
→ new Segment Descriptor identities
→ 后续 execution

而不是对原 descriptor 无限 retry。

vcec-r1n 继续固定为：

run outcome = abandoned
classification = historical-runtime-failure
reusable = false
authorizes = []

其内部历史 attempts 保留各自真实 attempt classification；
不得统一改写成 abandoned、不得删除，也不得升级成成功 evidence。


同时确认此前修正继续保持：

- D3：deterministic_evidence 不参与 Consumer Closure fixed-point，避免循环依赖。
- D4：Range Projection 使用 zero-based、start-inclusive、end-inclusive byte range，与 Canonical Spec 保持一致。
- D5：attempt identity 不进入稳定 Segment Descriptor；普通 transport retry = same descriptor + new attempt identity。
- D9：legacy verify-only replay capability 必须先建立，再迁移 mandatory consumers，避免 historical evidence validation gap。

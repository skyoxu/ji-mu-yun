## 1. 问题与目标

当前是单节点服务，域名/端口和本地路径不应成为账号归属身份。目标是在测试同机形态下明确入口与生产角色、稳定 node_id 与未来固定 home_node_id 合同，使后续接第二生产节点不需要推翻现有账号/项目身份。

只建设必要边界，不在 step2 实现完整自动多节点注册或真实跨机调度。同机仅测试，正式切割，不考虑测试用户和项目迁移。

## 2. 已有基础

复用 AccountSnapshot、ProjectSnapshot、RunSnapshot、RequestContext、既有 SQLite 元数据和项目 ownership。8-24 的逻辑身份与 Windows Runner 注册继续保留，node_id 不取代任何现有身份。

契约基于 ADR-0035/0036/0038/0061 与当前 SQLite 本地盘架构；多个节点不能共享一个 SQLite 文件作为网络数据库。

## 4. 最小合同和存储方向

逻辑项：node_id、role、endpoint、accept_new_accounts、capacity/readiness reference；账号归属 account_id→home_node_id；项目/run 引用实际所属节点。具体字段位置由 spec 选择，不要求在每个 artifact 复制全部字段。

中心负责账号状态/唯一归属；节点负责自身项目/文件/快照和执行。step3 通过服务协议交换最小投影，不靠节点打开入口的 SQLite 文件。step2 可同机验证职责，但不能将同机读写当跨机协议已通过。

缓存仅加速共享版本查询；中心账号/归属、节点容量承诺、通知发布事实及本地已读各保留其服务端权威。中心/节点角色可同机测试，生产时用鉴权协议交换最小投影，不直接读取另一主机的 SQLite 文件。通知投影不等于用户项目数据跨机存储。

## 5. 依赖与排除

本包可作为 step2 首包。S2-03A/B、S2-01/02、S2-04A/B、S2-05 依此稳定 scope；本包定义 capacity 接口，S2-03A 实现真实读模型，不形成实现循环。

不做用户自选节点、管理员人工分配、跨节点 Worker、账号动态迁移、测试项目搬迁、分布式数据库或第二对象存储后端。实际第二节点准入、注册自动分配、中心安全登录由 step3 完成。

## 6. 验收场景

| AC | 场景 | 结果 |
| --- | --- | --- |
| S2-06-AC01 | 同机测试两个逻辑角色和唯一测试节点 | 身份稳定，入口/生产职责清晰，当前项目可用 |
| S2-06-AC02 | 修改 endpoint/端口或浏览器伪造节点 | node identity 与归属不变，不允许错归属项目操作 |
| S2-06-AC03 | 服务重启/增量迁移 | 已绑定测试归属和项目 identity 一致 |
| S2-06-AC04 | 入口 production role 关闭 | 普通创建/执行消费者不运行，允许登录/路由/管理员职责 |
| S2-06-AC05 | 项目代码修改归属配置或访问中心元数据 | 无权更改，身份及密码权威受保护 |
| S2-06-AC06 | 尚未接真实节点协议 | 读回明确单节点测试范围，不声明自动多机已完成 |
| S2-06-AC07 | 同一物理节点启动多个 Runner 或已支持的 .NET 实例，改变进程诊断 identity | home_node_id/项目身份稳定，registry/capacity 不按实例数量重复计算，未支持拓扑明确拒绝 |
| S2-06-AC08 | 两账号使用同一已批准共享知识/demo，尝试将本账号项目当共享源访问 | 共享版本只读可消费，项目/快照/私有缓存仍按账号隔离，无跨机用户文件存储 |
| S2-06-AC09 | 中心/生产同机测试通知发布与本节点受众查询，再由项目伪造控制身份或 port | 职责明确，只有批准服务路径可消费保护投影；同机结果不冒充跨机同步已通过 |

## 7. 下游设计与交付

BMAD architecture 先冻结不可逆的中心/节点权威，再固化最小 node/归属接口。对当前配置、角色 dispatch、错归属和持久化做定向验证，不提前创建多机全套运维系统。

交付稳定身份/角色、兼容合同和当前测试接线。step3 可复用它们，但真实跨机成功必须另验。受保护 auth/runtime 配置改动按仓库规则处理，本文件本身不执行上线切割。

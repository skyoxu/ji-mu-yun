但还没有解决：

而这个正是 stage-recovery 项目的关键。

最小修法

不需要再动需求，只把 bridge 变成真正的 one-time migration state adapter：

no current RED handoff
+ planned test absent
→ materialize test
→ run RED
→ publish implementation-needed
→ stop


matching current RED handoff exists
+ test hash matches
+ contract/failure intent matches
→ DO NOT rerun RED
→ hand control back to normal Quick Dev continuation
→ GREEN / refactor


RED handoff stale/mismatch
→ fail closed / successor preparation

也就是说 _run_slice() 不能简单写成：

adapter_bridge exists
→ always run bridge

而应该是类似：

adapter_bridge exists
+ migration RED still needed
→ run bridge


otherwise
→ normal staged/compat continuation

最好补两个 targeted tests：

RED handoff exists
→ second invocation does not materialize/rerun RED
→ reaches GREEN continuation


RED handoff exists but contract/test hash drifted
→ does not reuse

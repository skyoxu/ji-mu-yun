2556ea78...

所以这个 ready=true 只能作为历史证据，不能作为当前 VDD Skill-input gate。

文件存在；

因此旧 receipt 可能被 terminal 错误接受。这是当前最高优先级问题。

P0-2：source graph 自引用仍然存在

旧 receipt 明确把：

95-implementation-evolution-and-completion-report.md

作为 required source。

而现有 generated_artifact_exclusions() 仍然只是文件名排除列表，仅排除：

skill-input*
semantic-input*
knowledge-context*
精确名称的 plan/resume state
精确名称的 authorization receipt

它没有系统排除：

95-* append-only report；
terminal/acceptance/implementation results；
versioned/successor state；
repair closure；
嵌套 lifecycle artifacts；
retry、page、sidecar 等临时产物。

因此即使现在重新生成 receipt，95 报告仍可能重新进入 source graph。W0 的类型化 source selection 必须先完成，不能靠再加一个文件名前缀解决。

P0-3：authority manifest 仍包含可变生命周期和实现文件

当前 authority-manifest.v1.json 仍把以下文件列为 authority source：

plan-state.v1.json
resume-state.v1.json
execution_control.py

这会产生新的自失效风险：

plan-state 在授权时必然变化；
resume-state 在每个切片后变化；
execution_control.py 又是 R0 允许修改的生产实现。

建议拆成三类：

authority_sources
candidate_inputs
lifecycle_projections

其中：

repository rules、Accepted ADR、生命周期合同、Skill 合同属于 authority；
implementation code、terminal、contract、registry 属于 candidate binding；
plan-state、resume-state 属于 lifecycle projection。

后两类不能进入稳定 authority source envelope。

P0-4：R3/R4 文本和机器合同仍然矛盾

requirements-and-acceptance.md 已经正确声明：

R3 是兼容性验证，不是新的 TDD RED；
R4 是 dogfood/replay，不实现新生产行为。

但是 implementation-contract.v1.json 仍为 R3/R4 定义：

tdd.red
expected_failure_ids
planned_new_files
生产代码写入权限

这仍违反当前 VDD 的规则：已经存在的行为必须作为 regression/terminal coverage，不能制造 synthetic RED。

建议：

把 R3 改为 execution_mode: regression；
把 R4 改为 execution_mode: dogfood-replay；
移除二者的 tdd.red；
R4 的 production write-set 应为空；
只允许写当前 8-18 目录下的新运行证据；
如果发现真实缺失行为，再新增一个明确的 implementation slice，不能复用 R3/R4 名义。

新建工作流修复计划的检查

把生产工作流问题拆到独立的 2026-08-18-toolchain-workflow-repair 是正确决定。

W0～W3 的方向基本正确：

W0：类型化 selection；
W1：adapter 控制分页和 continuation；
W2：adapter 控制 coverage；
W3：Knowledge 三门分离。

但它明确把 W4 和 W5 列为 non-goals，因此没有覆盖最初发现的全部六项缺陷：

W5：attempt lease、retention 和 GC。

其中 W4 已经直接阻塞当前 8-18 terminal，所以不能继续作为非目标。建议把 W4 加回同一计划；W5 可以留在同计划后置切片，或者拆成明确依赖 W0/W4 的后继计划。

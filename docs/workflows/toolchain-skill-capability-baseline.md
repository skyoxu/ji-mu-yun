## Integration and conflict checks

The original first baseline omitted eleven current 8-05 replay test modules. Both skills now include those actual runtime/integration cases: immutable validator trust, effective reads and positive/negative controls, matrix execution, consumer rollback, cumulative deadlines, process cleanup, fresh source reconstruction and Windows API fault simulation. These are current behavior regressions, not historical byte-oracle substitutions. The four original RMAP integration scenarios run as four explicit mandatory node targets so that existing scratch cleanup occurs between them; none is omitted or given a larger unit budget. The original S2 fixture was a v2 label matrix, which current production explicitly refuses as non-promotable. Its test now verifies that refusal and uses the existing public `prepare-matrix` command with the immutable approved replay baseline to generate a fresh v3 matrix; all six real Stable/Candidate scenarios and separate process evidence remain required, while the original v2 file stays unchanged.

The complete current native mandatory suites must exercise the same content identity before admission. Cache reuse still checks current permissions, source roles, owner/write boundaries and immutable originals; reference-only closed-episode recovery does not deliver or charge again. Refactor closure may retain historical GREEN only for the exact allowed production delta, while normal reentry/shared-execution freshness remains strict. Failure arrays and admission failure result-json have permanent real-entry regressions.

The legacy CH456 Windows harness must perform guarded candidate regression and admission before its ordinary metrics. The complete direct-pytest steps are replaced by the complete native mandatory sets, preserving assertions rather than bypassing entry guards. A wiring regression executes the checked-in command sequence through a real small runner and proves that a failed mandatory test prevents admission. Live metric commands and their backend configuration remain separate; their successful execution is not claimed here.

A later version requires real test increment and a new full successful measurement; bootstrap is not reset. Record final fingerprints and actual measurement in the delivery logs rather than inside this fingerprinted inventory.

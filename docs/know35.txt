3. Bootstrap：我赞成“通常不用”，但这是当前 contract 里真正需要改的一处

现在 run-phase-bootstrap-review 是正式的三角色 semantic review protocol，要求 Blind Hunter / Edge Case Hunter / Acceptance Auditor 隔离，P0/P1 再 independent verifier。

更重要的是，当前 Acceptance contract 规定：如果 typed route 是 full_implementation_conformance 或 focused_repair_verification，Acceptance 必须调用 Bootstrap；没有 required finalized Bootstrap envelope，就不能把 deterministic pass 当 acceptance pass。

所以目前不能简单写：

Acceptance says Bootstrap required
→ 我已经在网页版看过了
→ 跳过
→ acceptance-passed

这在当前 contract 下属于 authority bypass。

但我认为应该改成你说的模式

我会给工具链增加一个非常简单的supervised mode，而不是继续把 Bootstrap 当日常默认路径。

例如：

acceptance_mode =
  supervised
  | unattended
supervised

你人在这里主动操作：

VDD
→ web Sol review
→ maintainer authorization
→ Quick Dev
→ web Sol implementation review
→ Acceptance deterministic checks
→ acceptance-passed

Bootstrap：

optional

只在这些情况启动：

你主动要求；
Sol 复核发现高风险疑点；
security / permission / data corruption；
lifecycle / authority control 自身修改；
你希望做一次独立多角色 adversarial review。
unattended

没人盯着：

VDD
→ exact-cover
→ authorization policy
→ Quick Dev
→ Acceptance
→ typed Bootstrap route
→ Bootstrap when required
→ Acceptance finalization

这时候本地 Skill 的 durable evidence、隔离、retry、lease、三角色审查就重新非常有价值。

最重要的是：不要让“网页聊天内容”直接成为 Acceptance authority

我建议保持这个边界。

网页版 Sol 可以说：

“我检查了 commit X，没有发现实现阻塞问题。”

然后你作为 maintainer 做决定。

但不要把 ChatGPT 文本复制成：

{
  "model_said_pass": true
}

然后让 Acceptance 信任它。

更好的设计是：

Web Sol = advisory semantic reviewer


Maintainer =
  接受 / 拒绝这个建议


Acceptance =
  只相信 repository machine evidence
  + 一个非常小的 maintainer supervised-mode decision

例如一个机器 artifact：

{
  "mode": "supervised",
  "candidate": "<commit>",
  "decision": "semantic_review_satisfied",
  "owner": "maintainer",
  "authorizes": []
}

它表达的是：

“maintainer 已完成所需人工语义复核”

而不是：

“ChatGPT 的一句话拥有 acceptance authority”。

最终 acceptance-passed 仍然由 Acceptance 根据机器证据发布。

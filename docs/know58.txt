当前仍然存在的阻断项
P0-1：plan-state 自身不合法

当前状态是：

{
  "status": "plan-ready",
  "authorizes": []
}

但仓库当前 Quick Dev TDD 的授权门要求：

draft 对应 authorizes: []
plan-ready 至少应包含 authorizes: ["plan-ready"]

因此 Quick Dev 会将这个状态判断为非法状态，而不是合法的待维护者授权计划。

更重要的是，repair closure 尚未生成，按照当前 repair plan 自己的声明，也不应该提前转成 plan-ready。

相关文件：

plan-state.v1.json
repair-plan.md

修复建议：先退回合法 draft，完成 repair closure 后再由 VDD 原子地发布：

{
  "status": "plan-ready",
  "authorizes": ["plan-ready"]
}
P0-2：注册的 terminal 命令全部缺少必需参数

terminal_full.py 现在要求：

--repository-root
--plan-dir

但 command-registry.v1.json 中的 R0～R4 和最终 terminal 命令都没有传入这两个参数。因此这些“已注册验收命令”实际会在 argparse 阶段失败。

相关文件：

command-registry.v1.json
terminal_full.py

不要简单写死绝对路径，应该用现有 typed argv 机制表达：

repo_path
plan_path
slice_id

并为每条注册命令增加 registry execution test，验证命令经过 builder 展开后可以真实执行。

Slice W1：自动传输规划

增加：

semantic_input_mode = auto
max_inline_snapshot_bytes
max_page_bytes
max_total_snapshot_bytes
max_pages_per_batch

工作流在 frozen manifest 生成后自动选择：

小于 inline 阈值：单次 serialized snapshot；
超过 inline、低于 total：分页或批量分页；
超过 total：返回 source_graph_too_large typed route。

注意：当前 paged 模式仍受同一个 max_snapshot_bytes 总量限制，因此只是“传输形式分页”，并没有真正解决大目录预算问题。

还应加入：

多页单次 batch，避免每页一次模型调用；
基于 source hash + semantic contract + redaction profile 的页摘要缓存；
页范围、页哈希和完整覆盖 receipt；
预算耗尽和模型失败的可恢复 resume token。
Slice W2：把覆盖完整性从模型输出中移除

truncated 不应该由语义 child 判断。应由传输适配器根据真实分页覆盖计算：

{
  "coverage": {
    "status": "complete",
    "total_pages": 8,
    "consumed_pages": 8,
    "missing_ranges": []
  },
  "summary": {
    "mode": "bounded-lossy"
  }
}

Ready gate 只要求：

source manifest 完整；
page coverage 完整；
页哈希有效；
没有遗漏范围。

bounded-lossy 摘要是正常状态，不应阻断。

需要三个关键测试：

所有页已读取、摘要压缩：ready；
任一页缺失：blocked；
模型声称没有截断，但 adapter 检测到页缺失：blocked。
Slice W3：Knowledge 三门模型

不要再用一个状态同时控制执行、发布和评审。建议显式拆成：

{
  "execution_gate": "continue-degraded",
  "publication_gate": "blocked",
  "review_gate": "semantic-required",
  "reason_codes": ["query-evaluation-failed", "knowledge-self-change"],
  "authorizes": []
}

规则为：

catalog stale，但 selection 不变且源码可重新绑定：
execution=continue-degraded
TOOL-006 查询质量失败：
execution=continue-degraded
publication=blocked
当前 changed set 修改 Knowledge 系统：
review=semantic-required
self-change 且 semantic review 未完成：
terminal 禁止 implementation-complete
selection/authority/source 漂移：
hard blocked 或 typed repair

是否属于 Knowledge self-change 必须根据 canonical Knowledge path 和候选 changed-set 自动计算，不能让调用者用布尔参数自行声明。

Slice W4：统一 receipt 发布和发现

建议生成目录改为不可变 generation：

skill-input-generations/<binding-hash>/

并在计划根目录维护唯一的规范入口，例如：

skill-input-current.v1.json

发布过程：

在临时 generation 中生成；
完整验证；
原子发布 immutable generation；
原子更新 canonical pointer；
maintainer authorization 绑定确切 generation receipt。

Terminal 不应扫描“最新目录”，而应该：

有 authorization 时，从 authorization receipt 解析精确 generation；
尚未授权时，从 canonical current pointer 解析；
旧 skill-input-r*/receipt.json 仅用于兼容迁移，出现多个候选时必须报 ambiguity。
Slice W5：attempt 生命周期和清理

临时快照不应继续堆积在正式计划 source graph 中。建议：

原始临时数据放到 gitignored 工作区，例如 .skill-input-work/；
正式计划只保留 ready generation 和精简诊断 receipt；
生命周期：
active
failed
succeeded
expired
使用 lease/heartbeat，避免清理仍在运行的 attempt；
按年龄、数量、总字节三种预算执行 GC；
保留当前 ready generation、被授权绑定的 generation 和仍被 resume-state 引用的 generation；
失败原始分页数据按策略过期，只保留哈希、reason code、stderr 摘要和 cleanup tombstone；
提供 dry-run 清理命令和可审计 cleanup receipt。

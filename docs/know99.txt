review/authorization 校验还存在循环绑定错误

新 verifier 要求：

review_input.candidate.head_commit == git rev-parse HEAD
authorization.candidate_commit == git rev-parse HEAD

这是不可满足的持久化模型：

repair candidate 为 REPAIR_SHA
review 文件提交后，HEAD 变成 governance successor
authorization 文件再次提交后，HEAD 又变化
verifier 立即认为原 candidate 不等于 HEAD

正确规则应是：

candidate_commit == REPAIR_SHA
REPAIR_SHA 必须是当前 HEAD 的祖先
从 REPAIR_SHA 到当前 HEAD，只允许新增/修改 review、authorization、plan-state 等治理文件
contract、registry、selectors、stage runner 等受保护文件不得在 candidate 后变化
所有绑定文件 hash 必须仍然与当前文件一致

不能要求 candidate 永远等于包含 review/authorization 文件后的 HEAD。

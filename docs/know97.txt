三、六个 selector 的准确写法
S1：compiler 必须消费真实 manifest

当前错误是 selector 自己比较两个常量。

新 selector 使用 tmp_path 创建完整输入：

RUN-S1/
  semantic-intent-input.v1.json
  active-acceptance-manifest.v1.json
  semantic-verification-input.v1.json

其中：

active manifest 包含七个 acceptance ID。
semantic verification 只覆盖 A-SEMANTIC。
semantic intent 本身字段完整有效。

然后调用真实生产函数：

compile_run_local_semantic_artifacts(run_root)

预期行为：

try:
    compile_run_local_semantic_artifacts(run_root)
except ValueError as exc:
    assert str(exc) == "VDD-SEMANTIC-COVERAGE-MISMATCH"
else:
    pytest.fail("FAILURE_ID:VDD-SEMANTIC-COVERAGE-MISMATCH")

当前 compiler 不读取这两个 manifest 输入，会错误成功，因此 selector 真实变红。

Quick Dev S1 实施：

compiler 读取 active manifest 和 semantic verification。
调用现有 validate_semantic_verification_coverage()。
绑定两份输入的路径/hash。
只有 exact cover 才生成 semantic artifact。
S2：descriptor 必须绑定 semantic artifact

selector 构造一个其他字段全部有效、但缺少：

{
  "semantic_artifact_sha256": "..."
}

的 descriptor：

accepted, failure = validate_descriptor(descriptor)

assert (
    not accepted
    and failure == "QD-DESCRIPTOR-BINDING-INCOMPLETE"
), f"FAILURE_ID:{failure or 'QD-DESCRIPTOR-BINDING-INCOMPLETE'}"

当前 validator 会接受，因此是真实 RED。

Quick Dev S2 实施：

descriptor schema 要求 semantic_artifact_sha256。
必须是合法 sha256:。
produce_descriptor() 从真实 S1 evidence 派生该值。
不允许从输入自由声明。
GREEN 正常 descriptor 输入必须携带真实 hash。

测试名修改为：

test_descriptor_requires_semantic_artifact_binding

不要再叫 requires_case_sources，因为非空 case source 检查已经实现。

最后一个 P1：RED 后 router 仍然路由到 green，不是 implement

当前需求没有改，S0 明确要求：

RED run persists its summary and routes to implement.

但当前 production route_staged_run() 的逻辑是：

if state.stage == "red":
    if red-observed exists and red-basis exists:
        return "green"

run_slice_lifecycle.py 在 RED 完成后写的也仍然是：

{
  "stage": "red",
  "next_stage": "green"
}

因此现在 dogfood 实际是：

RED
↓
router says GREEN
↓
dogfood_runner 人工插入 implementation
↓
router still says GREEN
↓
GREEN

而不是：

RED
↓
router says IMPLEMENT
↓
implementation
↓
router says GREEN
↓
GREEN

也就是说：

独立 implementation action ✅
route-first stage recovery ✅
router 真正拥有 RED → implement → GREEN 状态机 ❌

这不是新 finding，就是上一轮“route-first + independent implementation”问题的最后半步。

最小修法

不要再动设计，只把状态机补完整：

RED observed
+ no matching implementation successor
→ route_staged_run = "implement"


implementation 完成
+ 当前 candidate 是 RED basis 的合法 successor
→ persist implementation successor/receipt
→ route_staged_run = "green"


GREEN observed
→ refactor


REFACTOR observed
→ slice-terminal

dogfood 相应变成：

_run RED
assert route == "implement"


独立 implementation
persist/bind implementation successor


assert route == "green"


_run GREEN
assert route == "refactor"


_run REFACTOR
assert route == "slice-terminal"

而且现在 implementation-action.v1.json 写在 dogfood-support/，route_staged_run(run_dir) 根本不会读取它。 最好把这个 receipt/成功 successor 变成 run-local、RED-basis-bound 的正式 stage continuity evidence，否则 production router 无法知道 implementation 已经发生。

P0-1：implementation-evidence.v1.json 现在可以“自报 PASS”

这是目前最关键的问题。

implementation-command.py 不会运行真实 validator/test。它只读取未来的：

implementation-evidence.v1.json

然后检查：

status == implementation-ready
implemented_commands 包含 command
commands[command].status == passed
acceptance_ids 非空
validation_reference 非空

之后直接返回 ready。

但它没有：

执行 validation_reference；
hash/revalidate validation artifact；
检查 production files；
检查 validator identity；
检查 receipt 是受控命令真实产生；
重新计算 acceptance predicate。

因此未来只要手写一个：

{
  "status": "implementation-ready",
  "implemented_commands": ["exact-cover"],
  "commands": {
    "exact-cover": {
      "status": "passed",
      "acceptance_ids": ["VCEC-A01"],
      "validation_reference": "anything"
    }
  }
}

这一 command 就能变绿。

这与整个 Exact-cover 的原则冲突：

prose / boolean / caller assertion 不能替代 deterministic proof。

必须让 command 自己执行验证，或者验证 hash-bound controlled-command receipt，而不是相信 evidence 声称自己 passed。

P1-2：Round 3 composition receipt 会被后续 terminal 覆写

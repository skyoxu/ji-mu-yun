唯一的硬阻断问题

同一个 prestart-40-request.json 目前存在三种哈希值：

当前文件 raw-byte SHA：1585d2a580bb...
当前文件 canonical JSON SHA：c14609498b6d...
Authorization receipt 声明值：012646b70f3f...

其中：

prestart-40-receipt.json 使用 c1460949...，与当前 request 的 canonical hash 完全一致。
implementation-authorization-receipt.successor.v1.json 仍保存 012646b7...，既不等于当前 raw hash，也不等于 canonical hash。
route_plan_directory.py 对所有授权绑定统一执行 _sha(path.read_bytes())，也就是 raw-byte 校验。

所以当前重新执行路由时，会得到：

next_action = awaiting-implementation-authorization
reason = implementation-authorization-stale

而不是要求的：

next_action = run-slice
slice_id = W0

因此现有 quick-dev-entry-receipt.v1.json 虽然写着 pass / run-slice / W0，但它已经不能被当前代码重现，不能作为可信入口证据。

达到 GO 的最小修复
让授权发布器和路由器统一使用共享的 artifact_identity_hash()，禁止各自实现 raw/canonical 判断。
给绑定增加明确的 identity_kind，例如：
{
  "path": ".../prestart-40-request.json",
  "identity_kind": "canonical-json-v1",
  "sha256": "sha256:c14609498b6d..."
}

非 JSON 源码使用 raw-bytes-v1。

更推荐让 Authorization 只绑定一个不可变 generation identity，例如：
{
  "skill_input_generation": {
    "receipt_path": ".../prestart-41-receipt.json",
    "generation_root": "sha256:...",
    "selection_hash": "sha256:...",
    "context_hash": "sha256:..."
  }
}

不要再重复绑定 request、context、decision 等表示文件的 raw hash。

由于 publish_implementation_authorization.py 本身属于当前 29 个选中源码，修复它属于真实的 selected-source 变化，因此需要最后一次合法的自动 successor，例如 prestart-41。这次 successor 是语义源码改变引起的，不是 HEAD 改变引起的。
重新发布 implementation authorization，再重新生成唯一的 Quick Dev entry receipt。
将旧 quick-dev-entry-validation.v1.json 移入 historical/noncanonical 路径，活动路径只保留一个当前入口结论。
